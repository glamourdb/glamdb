# Компактный Workbench

## Что изменилось

1. Вход через Keycloak показывает логин и пароль на одной странице.
   Workbench продолжает использовать OIDC: пароль вводится только на странице
   Keycloak. Восстановление пароля и включённый MFA остаются у провайдера входа.
2. В Data studio схема, Read rows и Write rows находятся на одной странице.
   Схема раскрывается над редакторами. Результат, количество прочитанных строк,
   идентификатор фактически прочитанного снапшота и экспорт находятся внутри
   Read rows. Это количество строк результата, а не всех просмотренных движком
   строк и не общее число строк коллекции.
3. Выбор снапшота обновляет метаданные и очищает предыдущий результат,
   сохраняя элементы формы, фильтры, лимит и черновик записи. Запрос не запускается
   автоматически: нажмите Run query. Старый незавершённый запрос отменяется.
4. Overview показывает схему рядом с количеством строк, колонок, снапшотов,
   файлов и названием подключённой базы. Большой рекламный баннер убран.
   Неизвестные серверу значения остаются неизвестными; Count rows доступен там,
   где нет API статистики. Схема коллекции фиксированная, без эволюции по снапшотам.
5. Style studio убран. Переключатель светлой/тёмной темы находится снизу меню.
   Меню на компьютере сворачивается до иконок. На телефоне остаётся выдвижным.
   В localStorage сохраняются только тема и состояние меню; токены, пароли и
   введённые строки туда не записываются.
6. Write rows содержит свёрнутые строки: раскройте Row 1, введите значения,
   добавьте следующую строку кнопкой Add row. Типы и NULL сохранены, JSON
   формируется автоматически. Batch editor остаётся дополнительным способом
   загрузки JSON. Неопределённый результат записи по-прежнему фиксирует исходный
   запрос и operation ID для безопасного повтора.
7. История и выбор снапшота упорядочены от новых к старым, когда у всех записей
   есть корректное время создания. Поддерживаются created_at_us, created_at_ms,
   timestamp_ms и ISO created_at. Если времени нет хотя бы у одной записи,
   порядок ответа API сохраняется; сортировки по ID нет. В истории время
   отображается в UTC, неизвестное значение отмечено явно.

## Темы без сборки

Редактируйте `ui/config/theme.json` или файл, переданный серверу как конфигурация
Workbench. Основные цвета отвечают за светлую тему, одноимённые `dark_` цвета —
за тёмную: например, `background` и `dark_background`. Размеры меню заданы
`sizing.sidebar_width` (208px) и `sizing.sidebar_collapsed_width` (64px). Существующее
автоматическое перечитывание конфигурации сохранено. Старые конфиги без `dark_`
получают запасную тёмную палитру. Сборка C++ для изменения UI не требуется.

## Переключение уже работающего Keycloak

Новый realm, созданный `apps.workbench_access.provision`, сразу получает
совместную форму. Для существующего realm нужен отдельный запуск команды ниже:
обычное обновление JavaScript не меняет конфигурацию провайдера входа.

1. Примените патч и пересоберите образ gateway из обновлённого исходного кода
   обычной командой развёртывания. Используйте уже настроенный compose проекта
   `deploy/access/compose.yaml`, его env-файл и приватную сеть.
2. Подготовьте пароль действующего администратора Keycloak в отдельном файле
   вне UI, с правами 0600 и владельцем, совпадающим с UID процесса gateway
   в контейнере (в стандартной конфигурации — 10001). Сопоставление UID и
   закрытых файлов описано в SSO_OPERATIONS.md. Не помещайте
   пароль в командную строку, Git или браузерное хранилище. Не восстанавливайте
   удалённого bootstrap-пользователя: используйте действующего администратора.
3. Если `dc` — уже настроенная в [инструкции SSO](SSO_OPERATIONS.md) функция
   compose, выполните (имя администратора и путь к файлу замените своими):

   ```sh
   dc run --rm --no-deps \
     -v "$ACCESS_ROOT/private/keycloak-admin.password:/admin.password:ro" \
     gateway python -m apps.workbench_access.login_form \
     --server https://keycloak-admin:18080 \
     --admin YOUR_ADMIN --password-file /admin.password \
     --ca-file /etc/glamdb/pki/caddy-root.crt
   ```

   С Docker используется настроенная функция `dc`; с Podman — её эквивалент,
   вызывающий `podman compose` с теми же файлами и переменными окружения.
   Сертификат и приватный адрес берутся из существующего развёртывания.
4. Команда создаёт копию browser flow с именем `glamdb-workbench-browser`,
   отключает только определение организации до ввода пароля и привязывает
   копию только к клиенту `glamdb-workbench`. Настройки организаций, членство,
   роли, разрешения баз, cookie SSO, MFA и запрет password grant сохраняются.
   Повторный запуск не создаёт второй flow. Необычная форма без обязательного
   username/password останавливает миграцию до привязки клиента: её нужно
   проверить в админке вручную.
   Автоматический перенос поддерживает стандартный встроенный browser flow
   и повторный запуск для уже настроенной принадлежащей клиенту копии.
   Нестандартный realm/client flow, неизвестная копия с тем же именем или
   flow, используемый другими клиентами/привязками, останавливает команду
   до изменения требований аутентификации. Это сохраняет обязательный MFA;
   такие настройки оператор должен проверить вручную.
5. В приватном окне браузера откройте защищённый Workbench → Sign in.
   Убедитесь, что поля логина и пароля видны одновременно, выполните вход и
   проверьте список разрешённых баз. Проверьте неверный пароль, восстановление
   пароля и MFA, если он используется. Существующая SSO-сессия может пропустить
   форму — для этой проверки нужна новая сессия.

Для отката в Keycloak откройте realm glamdb → Clients → glamdb-workbench →
Advanced → Authentication flow overrides → Browser flow и сбросьте override
к исходному realm flow. Встроенный browser flow команда не изменяет. После
отвязки при необходимости удалите только созданную копию.

## Проверка

Unit: `cd ui && npm test`; вход: из корня
`python -m pytest tests/access/test_login_form.py -q` в окружении проекта.
Браузерные сценарии: `cd ui && GLAMDB_TEST_BACKEND=mock npm run test:e2e`.
Для опубликованной статической сборки:
`GLAMDB_TEST_BACKEND=static npm run test:e2e`.
Настоящий сервер по-прежнему выбирается существующим native-профилем, который
требует `GLAMDB_NATIVE_SERVER`; изменение раскладки не переключает его на моки.
